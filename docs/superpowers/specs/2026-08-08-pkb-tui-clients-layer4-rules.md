## Read this first

Five findings are load-bearing enough to state up front. Each one would have failed **silently** —
the code compiles, the tests pass, and the guarantee is fiction.

| | What the specs assume | What the packages and the built code actually do |
|---|---|---|
| **P-10** | Layer 3 §5.4 ships the layer list `"(pkb.server) \| (pkb.tui) \| (pkb.clients)"`, ready for step 4. | **That list forbids the one import `pkb.clients` exists for.** `\|` is import-linter's *independent* delimiter, so siblings may not import each other. Verified on a throwaway tree: `zz.tui is not allowed to import zz.clients` **and** `zz.server is not allowed to import zz.clients` — i.e. both the TUI's and step 5's Telegram adapter's use of the shared approval helper. | **P-11** | `httpx2.AsyncClient` is a reasonable default for a streaming client. | **Its default read timeout is 5.0 s and that kills every real turn.** Verified against a live uvicorn socket serving the real app: an 8 s gap before the first `message.delta` raised `ReadTimeout after 5.00s`, having received only `run.started`. CLAUDE.md measures ~16 s per model call on the default model and 284 s per turn on the local fallback. Worse, AP-7 says a dropped connection *detaches*: the run continues, files the note, and the human is looking at a network error. Separately verified: the server's `: ping` comment frames **do** reset httpx2's read timer (`read=2.5 s` survived a 6 s silence at `ping=1 s`) even though `EventSource` never surfaces them — so a finite timeout above `PING_SECONDS=15` is both safe and better than `read=None`. |
| **P-12** | SS-4: the envelope is `type, seq, run_id, thread_id, agent_id`, so a decoder subtracts those keys. | **`status` means two unrelated things and is not in `ENVELOPE_KEYS`.** Verified against the real encoder: `subagent.end` carries `"status":"failed"` as a **dataclass field** (LB-15's delegate outcome) while `run.end` carries `"status":"interrupted"` as a **Layer 3 envelope field**. | **P-13** | Arch §6: the approval modal renders the diff; SS-11 says render `description`. | **Colouring it with a diff lexer lies to the human on an irreversible write.** Verified: `rich.syntax.Syntax(desc, "diff")` over a real *new-file* description painted `- Pull at 130F` and `- Rest 10 minutes` in ANSI 91 — the deletion colour — because markdown bullets look like diff removals. `describe_write` emits a unified diff **only** for an existing file; a new file gets `Proposed content:` and raw markdown. | **P-14** | Arch §9 / L3 §6.1: the TUI pilot tests "against the same stub". | **Two independent process-global landmines make that sentence wrong as written.** (a) `httpx2.ASGITransport` **buffers**: verified over the real app, six frames all arrived at t=0.001 s, spread **0.0 s** — every timing rule is untestable and a test claiming "the reply grows token by token" passes over a client that renders it all at once. The corrected approach for each is in §2 and carried into the rule table.

### Decisions applied on top of the mined recommendations

| # | Decision | Why |
|---|----------|-----|
| **H** | **`pkb.clients` gets its own import-linter layer, strictly below `"(pkb.server) \| (pkb.tui)"`.** The list becomes `["(pkb.server) \| (pkb.tui)", "(pkb.clients)", "(pkb.service)", "(pkb.agents)", "(pkb.packs)", "pkb.contracts", "pkb.core"]`. | P-10: §5.4's list as written is BROKEN the moment either intended importer exists. The corrected list was executed and is KEPT. It also buys something §5.4's did not: `pkb.clients` sitting *below* `pkb.agents` makes "the approval helper never touches the harness" a **layers** fact as well as a forbidden-contract one, and it catches `pkb.clients -> pkb.tui` (verified). |
| **I** | **`pkb.clients` is transport-free and UI-free — no `httpx`, no `httpx2`, no `textual`, enforced by its own `forbidden` contract.** The pure SSE decoder lives in `pkb.clients.sse`; the httpx2 wrapper that iterates a response lives in `pkb.tui.client`. | Step 5's `pkb.server.telegram` imports `pkb.clients.approval` and calls `PkbService` **in process** (D9); MC-7's built test asserts the Telegram adapter pulls no HTTP client. If any module under `pkb.clients` imports httpx2, that assertion becomes a discipline about *which submodule you happen to import* rather than a structure. A one-line contract makes it structural. The decoder itself needs nothing but `json`, `dataclasses` and `pkb.contracts` (verified: a 40-line decoder round-trips all nine kinds), so the split costs nothing. |
| **J** | **The decoder returns a `Frame` record — envelope plus the event — never a bare `AgentEvent`.** `thread_id`, `seq`, `status` and `code` are envelope-only and belong to no dataclass. | Verified: the *only* payload keys that are neither envelope keys nor dataclass fields are `status` (on `run.end` **and** `run.error`) and `code` (on `run.error`). A decoder returning only the dataclass throws away SS-9's `interrupted` and AP-11's `code: "cancelled"` — which is precisely the bug Layer 3's own suite found and fixed server-side, re-introduced one layer up, and it renders a parked thread as "done". |
| **K** | **Envelope stripping is field-driven, never key-driven.** Build each dataclass from `{k: v for k, v in payload.items() if k in dataclasses.fields(cls)}`. | P-12. The key-driven form is the one an implementer writes first and it destroys `SubagentEnd` — i.e. it breaks only on fan-out runs, the case a TUI is hardest to exercise by hand. Field-driven is also total: a tenth `AgentEvent` kind decodes with zero client changes, which is what makes `EVENT_NAMES`' import-time totality assertion worth having. |
| **L** | **`GET /threads/{id}` is the conversation; the stream is additive.** The TUI renders history from the detail payload and treats an attach stream as a live tail with an unreliable prefix. | Read in the built code (`pkb/service/runs.py`): `RunHub` keeps only the **first** `REPLAY_BUFFER_SIZE=512` frames (`if len(self._replay) < REPLAY_BUFFER_SIZE`), and `subscribe()` pushes that buffer into a queue of `maxsize=257` under `contextlib.suppress(asyncio.QueueFull)`. A long run's attach therefore has a hole in the middle, and the fresh encoder renumbers `seq` contiguously so the hole is **undetectable on the wire**. Rendering an attach stream as the conversation shows a turn with a silent gap. |
| **M** | **Per-run client state is keyed on `thread_id` and re-keyed on every `run.started`.** The cancel target is the run id from the **most recent** `run.started`, or from any frame's envelope on an attach. | Read in the built code: `RuntimeService.resume` does `minted = mint_run_id()` (`runtime.py:307`) — a resume continues the *turn*, not the run id, contradicting RO-12 and §5.2 row 6. And `DELETE /runs/{unknown}` is a deliberate 204 (RO-18), so a client holding the pre-interrupt id cancels **nothing and reports success**. The stub reuses `run_id="run-1"` for `start_run` and `resume`, so a suite written against the stub alone cannot see this (§6.4). |
| **N** | **The approval modal renders `description` as plain text unless the description contains a `@@` hunk header.** No lexer, no colour, no reflow otherwise. | P-13. `describe_write` emits five distinct shapes and only one of them is a diff. Colouring the others tells the human that lines being *added* are being *deleted*, on a write with no undo (D6). `@@` is the observable marker that the server actually produced a diff. |
| **O** | **`seq` is a per-response ordering cursor and nothing more.** No client dedupes, persists or correlates by `(run_id, seq)`. | Verified: two `SseEncoder`s over one `RunHandle` number the same `MessageDelta` `seq=1` and `seq=0`, because `routes._stream` constructs a fresh encoder per response. `SS-5`'s "per-run monotonic cursor" is false as built. A transcript keyed on `(run_id, seq)` silently overwrites the first half of a resumed run with the second. |
| **P** | **The problem-body `code` strings move into `pkb.contracts` and are re-exported from `pkb.server.errors`, identity-tested.** A one-constant seam amendment, in the same commit as step 4. | RO-21 tells clients to branch on the machine `code`; the table lives in `pkb.server.errors`, which `pkb.tui` and `pkb.clients` may never import (verified BROKEN under any correct layering). The only alternatives are a duplicated nine-row table in step 4 and again in step 5 — exactly the drift C-1 and C-8 were written to prevent — or a client that branches on prose. `validate_decisions`, `expert_thread_id` and `UnknownThreadError` already set the precedent: a name both sides must agree on lives in the seam. |

## 0. Conventions

Same severity convention as Layers 1–3. **Rule ids are stable**; a test that changes must cite the
rule that changed. Every test assertion says **no key** or **live**. Spoiler: **nothing in this
layer needs a live model** (§6.4).

### 0.1 Hard constraints inherited

- **I2** — `pkb.tui` and `pkb.clients` never import `deepagents`/`langgraph`/`langchain`/
  `langchain_core`, and never import `pkb.agents`. Layer 4 **widens** the ban (TU-2): also no
  `pkb.server`, no `fastapi`, no `starlette`, no `sse_starlette`. The TUI talks HTTP to the daemon.
- **I3** — Layer 3 and above write **nothing** under `kb_root`, by any path. Layer 4 additionally
  reads nothing under it.
- **Everything mechanical already exists below.** A client cites a rule; it never contains a second
  implementation of validation, diff rendering, decision validation, id derivation, event
  normalization or wire-name mapping. In particular the diff a human approves is rendered
  **server-side** into `ActionView.description` (RT-34, RT-35), and a client that re-read the tree to
  build its own could not do so under I2 anyway (SS-11).

### 0.2 Package layout (extends arch §3, Layer 3 §0.2)

## 5. The exact contract

### 5.1 `pkb.clients.sse` — the decoder

```python
# pkb/clients/sse.py — stdlib + pkb.contracts ONLY (CL-1, DC-1, decision I)
_BY_NAME: Final = {name: cls for cls, name in EVENT_NAMES.items()}      # SS-3, inverted once
_FIELDS:  Final = {n: frozenset(f.name for f in dataclasses.fields(c))  # decision K
                   for n, c in _BY_NAME.items()}
TERMINAL: Final = frozenset({EVENT_NAMES[RunEnd], EVENT_NAMES[RunError]})
RUN_STATUSES: Final = ("completed", "interrupted", "cancelled", "error")  # FOUR (DC-6)

@dataclass(frozen=True, slots=True)
class Frame:
    type: str                     # the wire name
    seq: int                      # per-RESPONSE ordering cursor only (DC-16)
    run_id: str
    thread_id: str                # the pane this frame belongs to (SS-10, TU-26)
    agent_id: str
    event: AgentEvent | None      # None only for run.started
    handle: RunHandle | None      # set only for run.started (DC-4)
    status: str | None = None     # terminal frames only (DC-5)
    code: str | None = None       # run.error only; OPEN SET (DC-7)
    @property
    def terminal(self) -> bool: return self.type in TERMINAL

def decode_frame(name: str, data: str) -> Frame | None:   # None = unknown name, logged (DC-4)
    payload = json.loads(data)
    if name == RUN_STARTED_EVENT:
        handle = RunHandle(run_id=payload["run_id"], agent_id=payload["agent_id"],
                           thread_id=payload["thread_id"])
        return Frame(..., event=None, handle=handle)
    cls = _BY_NAME.get(name)
    if cls is None:
        return None                                        # daemon newer than client
    kwargs = {k: v for k, v in payload.items() if k in _FIELDS[name]}   # FIELD-driven (DC-2)
    if cls is InterruptEvent:
        kwargs["request"] = decode_request(payload["request"])          # CL-19, one parser
    terminal = name in TERMINAL
    return Frame(type=payload["type"], seq=payload["seq"], run_id=payload["run_id"],
                 thread_id=payload["thread_id"], agent_id=payload["agent_id"],
                 event=cls(**kwargs), handle=None,
                 status=payload.get("status") if terminal else None,   # NEVER read generically
                 code=payload.get("code") if terminal else None)
```

### 5.2 `pkb.tui.client` — the transport

```python
SSE_TIMEOUT  = httpx2.Timeout(10.0, read=45.0)   # > PING_SECONDS=15, three missed beats (DC-9)
JSON_TIMEOUT = httpx2.Timeout(10.0)              # one indexed SQL read (DC-10)

async def stream(client, url, *, method="POST", json_body=None) -> AsyncIterator[Frame]:
    saw_terminal = False
    async with client.sse(url, method=method, json=json_body, timeout=SSE_TIMEOUT) as source:
        r = source.response
        if r.status_code == 204:                 # RO-17 idle — BEFORE EventSource (DC-11)
            return
        if r.status_code >= 400:
            await r.aread()                      # streaming responses hold nothing (DC-12)
            raise PkbHttpError(r.status_code, r.json())      # .code, .detail, .retryable
        try:
            async for sse in source:             # comment pings never arrive here (DC-8)
                frame = decode_frame(sse.event, sse.data)
                if frame is None:
                    continue
                yield frame
                if frame.terminal:
                    saw_terminal = True
                    break                        # never read past the first terminal (C-16)
        except httpx2.HTTPError as exc:
            raise StreamEnded(url, cause=exc) from exc       # outcome UNKNOWN (DC-14)
    if not saw_terminal:
        raise StreamEnded(url)                   # a clean EOF is just as unknown
```

## 7. Explicitly out of Layer 4

**Already Layer 1 or 2 — cite it, never reimplement it**
- The diff and the validation label inside an approval. `gates.describe_write` renders both
  server-side, once (RT-34, RT-35). Layer 4 displays; it does not compute (TU-39, TU-40).
- Which decisions an action allows. `ActionView.allowed_decisions` is server-side truth; a client
  narrows and never widens (RT-32, RO-15, CL-9).
- Decision validation. `pkb.contracts.validate_decisions`, imported by identity (CL-3).
- Thread-id derivation. `expert_thread_id`/`librarian_thread_id`/`is_scan_thread` from the seam
  (DC-20, TU-26); the rule that a routed thread is `<parent>::<agent-id>` is LB-14's.
- Event normalization, deduplication and the nine-kind union (RT-41, RT-43). The wire names come
  from `EVENT_NAMES`, inverted, never copied (DC-1).
- The merged reply, the expert roster, the per-expert statuses, the filed-paths list (MC-10, TU-28).
- The gate table, the deny list, the write lock, the flush, the 3-attempt bound, the escalation.

**Already Layer 3**
- The `AgentEvent` → frame envelope, `run.end.status`, the synthesized `run.error code=cancelled`,
  the replay buffer, the run supervisor. Layer 4 consumes them and adds nothing to the wire.
- The typed-error → status map. Layer 4 branches on `code` (DC-12) and never re-maps.
- Thread minting, listing, ordering and grouping (SV-10, RO-6, RO-7). The client renders the order
  it is given (TU-8, TU-10).

**Step 5 — `pkb.server.telegram`**
- Inline keyboards, message splitting on Telegram's length limit (**never on meaning**, LB-18), the
  `chat_id` → `agent_id` mapping (TG-1), and any `message.delta` consumer (editing per token hits
  the rate limit). Step 4 builds only `pkb.clients.approval` in the shape both channels can use —
  which is why CL-1 and decision I matter more than they look.

**Deferred**
- Auth, credentials, TLS, non-local daemon topology (arch §10, AP-20 — the daemon binds localhost).
- `Last-Event-ID` gapless replay across a new request. Note that L3 §7's claim that `seq` keeps this
  "additive" is **false as built** (C-17): a real fix needs the hub, not the response, to stamp
  `seq`. `GET /threads/{id}` closes the gap on a personal KB.
- Watching another channel's live stream. D3 means shared **state**, not shared **streams**.
- Applying a `PendingProposal` — a Layer 2 entry point (L3 Q3). v1 lists and dismisses (TU-20).
- Creating a topic from the UI (a gated agent flow, LB-7); editing KB files directly (I3); search
  across threads; multi-daemon or multi-user; an ACP adapter (arch §10).
- A conflict-scan trigger and a conflict inbox — no route exists, and adding one is a Layer 3
  amendment (Q17).

**Never, at any layer**
- **A model call from a client**, of any kind, for any reason (TU-5).
- **Any read or write under `kb_root`** from `pkb.tui` or `pkb.clients` (TU-4, I3).
- **A second diff renderer**, or reconstructing proposed content from the rendered diff. The diff is
  context-limited (`n=3`), so the bytes would differ subtly from what the human read — the one thing
  an approval must never do (TU-39, TU-44).
- **Parsing the merged Librarian reply** to recover thread ids, filed paths, expert names or menu
  candidates (TU-18, TU-28, C-25).
- **Branching on `origin_channel`** to permit, refuse or route anything (TU-17, RO-22).
- **Widening `allowed_decisions`**, padding a partial approval with a default, or substituting a
  tool on an edit (CL-6, CL-9, CL-15).
- **An automatic retry of a run**, at the transport level or above (TU-32, TU-34, SS-5). There is no
  undo (D6), and the first run may already have written.
- **Deriving anything from `seq` across two responses**, or reading a `seq` jump as a lost frame
  (DC-16).
- **Running the SSE pump outside a Textual worker**, or awaiting a human decision inside it
  (TU-22, TU-23).
