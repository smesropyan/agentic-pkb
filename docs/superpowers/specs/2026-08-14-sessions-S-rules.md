# Sessions — `S-*` Rules (`DESIGN.md` §2)

**Date**: 2026-08-14
**Status**: Minted. Task 1 of `docs/superpowers/plans/2026-08-14-phase2-sessions.md`; no code changes
yet. Tasks 3–9 of that plan build the session store, the session file writer and the routes against
this contract.
**Scope**: the session layer `DESIGN.md` §2 ("Sessions") specifies — a durable named thing with one
file for its whole life, reached through channels that attach to it. Where §2's own sentences send a
concept elsewhere, this file sends it too: session-file *frontmatter* fields were already fixed by
the `T-*` rules (`docs/superpowers/specs/2026-08-13-tree-T-rules.md`, its §1.3/§1.9 — `T-9`, `T-34`);
a Librarian round's own mechanics (fan-out, the merge, the three-part reply, no debate) are §5's
workflow, minted later as `W-*`; the content the Learning agent's analysis may conclude, and the
worker that drains the queue, are §7's, minted later as `L-*`; and the rendering a TUI or a Telegram
client gives a channel list is Phase 5's polish over the API this file fixes.

## 0. How to read this document

`DESIGN.md` §2 is the one source. Where a rule's text is a direct quotation the cell says so with
quotation marks; where it collapses several sentences of prose into one testable assertion the cell
paraphrases and the section heading is the citation. **Rule ids are stable** — a docstring or a test
that implements a rule cites its id (`CLAUDE.md`, "Conventions"), and changing behaviour means
changing the rule here first.

**Severity convention.** For a rule the session store or the session file writer enforces
mechanically on a call — a state-machine transition, a write-path refusal, a section's presence,
a route's existence — severity states how a violation fails: `error` = the call must raise, the
write must be refused, or the file must be structurally wrong; a defect Tasks 3–5 must not ship.
`warning` = a rule this file records for a later phase to honor, where no single Layer 3 mechanism
enforces it alone — the check lives in agent judgment (Phase 3), in the analysis the Learning agent
drafts (Phase 4), or in client UX (Phase 5) built over the API contract this file does fix. A
**boundary row** carries `—`: it asserts nothing of its own, and exists so a later phase does not
re-derive from `DESIGN.md` a scope this file already drew.

**The two rulings** the plan records above its task list are minted here rather than left as prose:
P3 (the on-disk seal is an appended `## Ended` marker entry plus the store's `state='ended'`, checked
at the store rather than parsed from the file) is **S-24**; P4 (the learning queue is the set of
`state='closed'` sessions ordered by `closed_at`, a view rather than a second stored structure) is
**S-25**. Both were the operator's call where §2 is silent, ruled 2026-08-14, and stay marked
**RULED** rather than folded silently into the numbered sequence, so a reader can still tell a plan
proposal's provenance from `DESIGN.md`'s own word.

**Every rule id below is stable and must be referenced in the test that covers it.**

### 2.9 The expert argues with the operator, and about the operator's own conclusions

| ID | Rule | Sev | Test assertion |
|----|------|-----|-----------------|
| S-37 | "A good expert objects during the work rather than in a retrospective... The same holds when the analysis runs, where the operator can be wrong.
